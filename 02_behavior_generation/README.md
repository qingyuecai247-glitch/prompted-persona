# LLM response generation

`layers-llm.py` performs persona-conditioned questionnaire generation, repeated responses, domain scoring/aggregation, token accounting and JSONL/CSV export. `server_vllm.py` serves a local model; it is not a study-design or scoring program. `enrich_description.py` optionally expands situation/image descriptions into longer factual descriptions; it does not enrich persona biographies. Its inclusion does not establish that the step was used in the final study.

## Configure inputs and backend

Install requirements-generation.txt at repository root. Set PERSONA_GENERATION_DATA to the directory containing the retained instruments and inputs, and PERSONA_GENERATION_OUTPUT to a new output directory for each run. Inputs and questionnaire/situation material are supplied separately.

The main generator reads PERSONA_PROFILE_CSV, PERSONA_BIG5_QUESTIONS, PERSONA_SITUATION_JSON, PERSONA_STATE_QUESTIONS and PERSONA_SITUATION_FEATURES. Persona CSV needs name, description and first_person columns; situation-feature CSV needs id_s and the eight DIAMONDS columns.

For local generation set PERSONA_MODEL_SOURCE=local and PERSONA_LLM_URL to your running service's /v1/chat/completions endpoint. For Azure set PERSONA_MODEL_SOURCE=azure, AZURE_OPENAI_ENDPOINT, AZURE_OPENAI_API_KEY, AZURE_OPENAI_API_VERSION and PERSONA_MODEL_NAME (deployment name). No endpoint or secret is embedded. PERSONA_MODEL_KEY selects the retained token-cost lookup; pricing values are historical configuration, not current quotations.

```sh
python 02_behavior_generation/layers-llm.py
```

PERSONA_START_INDEX controls resume position (retained original default540; set0 to start at the first input row). PERSONA_BIG5_REPEATS and PERSONA_STATE_REPEATS retain original default5. Scoring keys, prompt content and aggregation logic are retained from the supplied source, rather than silently adjusted to manuscript descriptions. The code's existence is not a claim that every model dataset was generated by this exact configured copy. Outputs may replace files in the selected run directory.

## Local model service

Select compatible vLLM/PyTorch/CUDA dependencies using requirements-serving.txt, set CUDA_VISIBLE_DEVICES if needed, then:

```sh
python 02_behavior_generation/server_vllm.py --model /path/to/model --port 3000
```

This custom endpoint returns a JSON string containing generated text; it is not a complete OpenAI server implementation. The generator accepts this response format. The service binds to loopback by default.

## Optional situation-description preprocessing

Set PERSONA_SITUATION_INPUT and PERSONA_SITUATION_ENRICHED if using other paths, and PERSONA_LLM_URL for the running service, then:

```sh
python 02_behavior_generation/enrich_description.py
```

No inference or data regeneration is launched by installation, tests or the statistical reproduction wrapper.
